## 打开时的入场序列

打开页面（手机和电脑一样）先跑约 2 秒的启动动画：网格从中心铺开 → 准星锁定 → 终端逐行打日志 → 进度条走满 → 一圈光环炸开、遮罩散掉，树已经在里面了。

它不是"盖个 loading 再撕开"。遮罩拆成了两层：

- **暗场**在 35% 左右就退掉 —— 树能从界面底下透出来，边透边长
- **HUD**（网格 / 准星 / 日志 / 进度条）留到 70%，跟光环爆发一起散

树本身是按**真实高度逐层点亮**的（顶点着色器里 `u_reveal`，每个粒子看自己的世界高度），生长前沿还有一道窄亮带。所以树是"从树底往上长"，不是整体淡入。

几点细节：

- 点一下屏幕可以快进到收尾，不用等满
- 手机上默认 2.15 秒，桌面 2.45 秒；系统开了「减少动态效果」会压到 0.6 秒
- 爆发那一下会让整棵树轻颤 0.055（复用摇一摇的通道），手机同时短震
- 序列结束后遮罩节点直接从 DOM 移除，不留合成层

## 手机端的授权门（三步互动确认）

手机竖屏打开后，先出现一套 HUD 授权界面，要手动确认三步才放行：

| 步 | 标题 | 确认方式 |
|---|---|---|
| 01 `AUTHORIZATION` | 需要访问许可 | **点按**「授予访问权限」按钮 |
| 02 `IDENTITY` | 身份资料确认 | **长按**按钮 0.9 秒，底部进度条走满才算过 |
| 03 `SYNC` | 开始读取权限 | **滑动**滑块拖到最右端 |

三步过完先亮「核验通过 / READ COMPLETE · VERIFIED」，随后才把画面交给树的生长序列。
右上角有「跳过 SKIP」，不想点就直接进。

版式照着参考片子的那一套走：宽字距中文主标题 + 全大写英文副标题、细线四角框、括号按钮、
左下 `01 / 03` 步进、底部中英双语状态行，还有极淡暗网格和缓扫光带。

- 每种确认都有短震动反馈；长按中途松手会回弹并抖一下，提示"没按够"
- 系统开了「减少动态效果」或桌面端不显示这道门（`?gate=1` 可强制打开，`?gate=0` 强制关闭，`?gatestep=2` 直接跳到某一步）

## 祝福语与收礼人

左上角标题下面就是那句祝词：

```
AURORA-7
圣诞快乐            ← 流光扫过，颜色在青白之间走
MERRY CHRISTMAS
致 · 所有人          ← 点一下改写给谁
来自 老李 的祝福      ← 只有从别人的链接进来时才出现
```

点「致 · 所有人」弹出来的是**两个字段**：

- **致**：收礼人，显示在"致"后面
- **来自**：送礼人，显示成下面那行小字，留空就没有这一行

各限 12 字，存在本机（`aurora.to` / `aurora.from`），不上传。
键盘 `Enter` 确定，`Esc` 取消，清空就是写给所有人。

**一条链接就是一份礼物**：分享出去的地址里带着 `?to=小王&from=老李`，
对方打开就是「致 · 小王」+「来自 老李 的祝福」，入场结束后还有一句「老李 送给你的」。

> 从链接进来的人是改不动"这棵树是谁送的"这层意思的 —— 他改「致」是在准备转送给下一个人，
> 改「来自」才会把自己名字加上去。所以一封礼物可以一直往下传。

整套 UI 只有一个字体族（等宽），祝福语也没有换花体 —— 花体一放进来就跟整个 HUD 打架。

## 分享与二维码

右上角「送给 TA」，按一下：

- **手机上**：直接调系统分享面板，微信 / QQ / 短信都在里面，标题和文案里带着收礼人的名字
- **桌面上**：弹一张二维码，手机扫一下就把这条链接带走
- 系统分享被拒（不是你自己点的取消）会自动退回二维码
- 名字长到连版本 9（232 字节）都塞不下，就退回复制链接，并明确告诉你复制了

二维码是**自己实现的**（脚本里 `1.5 QR 编码器` 那一节：byte 模式 + 纠错 L + 版本 1-9），
没有引任何 CDN —— 单文件、离线、断网都能用。生成时八个掩码各试一遍，取罚分最低的那个。
画的时候每模块都落在整数物理像素上：缩放插值会把边缘糊掉，扫码就吃亏。

## 流星许愿

入场结束后，夜空里会不定时划过一颗流星（前两颗隔得近些，5~9 秒一颗，之后拉到 10~19 秒）。
点在它身上就收下一颗**愿望星**，左上角会多一个计数，同时原地炸一小朵烟花。

收满 **5 颗**触发彩蛋「极光爆发」：

- 全屏铺一层流动的极光雾（CSS 混合模式 `screen`，4 秒淡出）
- 整棵树闪一下、晃一下，连放 4 朵烟花
- 祝福语从青白转成金色，并一直保持金色
- 系统播报：「愿望已应验，极光为你展开」

流星是屏幕空间的 DOM 元素（不是 WebGL 粒子），因为要能用手指点中；
命中区比可见光点大一圈（52×30），尾迹是它内部旋转出去的一条渐变线。

## 声音：开场八音盒 + 整首歌 / 科技语音 / 轻音效

**主曲是 `bgm.m4a`**（Every Summertime - NIKI，把 96kHz/24bit 的 FLAC 转成 44.1kHz 立体声 AAC 128k，
80MB → 3.5MB）。源合成曲只保留**开始动画**那一段过门，其余全部让位给整首歌：

- 开屏动画一开始就起合成音乐（3/4 拍八音盒，88 BPM），调度器只往前排到 `introUntil`，
  到点自动收工，不会再多排一个音符
- 交接是交叉淡入淡出：合成谱 0.45s 衰到 0，歌在同一个 GainNode 上从 0.0001 抬到 0.72
- 跳过开屏（点一下 / `?boot=0`）时 `AU.cutIntro()` 把收尾提前到 0.34s，不会留一段空场
- 歌 `loop` 循环，首尾带淡入淡出，接缝处不会"啪"一下
- 外挂曲起不来（文件缺了、解码失败、被拦）→ `resumeSynth()` 把合成谱接回来，宁可回到老样子也不哑
- 播放/暂停、切后台、语音播报 duck 都作用在同一个 GainNode 上
  （以前直接改 `el.volume`，会跟淡入互相打架）

换一首：`?bgm=./别的文件`；`?bgm=0` 关掉外挂曲、只听合成音。

开场那段合成本身：

- 三层织体：低音（每小节根音，正弦 + 高八度弱层，否则手机小喇叭等于没低音）、
  和弦垫（四个常驻声部，每小节滑到新和声）、旋律（八音盒音色）
- 和声 `Cmaj7 → Am7 → Fmaj7 → Gadd9`，8 小节一个乐句；第 9 小节抬高八度做变奏，再回主句
- 八音盒音色 = 基音 + 二次泛音 + 一个很短的"叮"（三次泛音）。三条泛音**并联**汇合、各自独立包络；
  串到主包络上会被乘两次，泛音全被平方压掉 —— 这是更早一版听起来发闷的直接原因
- 节奏用**提前排谱**（每 250ms 往前铺 0.9 秒）而不是每拍一个定时器，主线程卡一下也不会把节奏推歪

切光效模式不再换调（整首歌是固定的），只有画面和音效跟着变。

> 《星光下的梦想》是受版权保护的曲子，没有把旋律转录进代码；开场那段是按"星光 / 温柔圆舞曲"
> 另写的。《Every Summertime》是你自己提供、托管在本目录里的音频文件。

**科技语音**用的是系统 TTS（`speechSynthesis`），pitch 0.80、rate 1.05，配两声玻璃确认音，
播报时音乐自动 duck 到 34%。手机上的台词：

| 时机 | 台词 |
|---|---|
| 第 2 步 | 身份核验中，请长按按钮 |
| 第 3 步 | 权限同步中，请向右滑动 |
| 三步通过 | 权限已授予，正在唤醒极光矩阵 |
| 树亮起来 | 极光矩阵已唤醒 |
| 桌面直接进 | 极光矩阵在线 |

**交互音效**（`AU.sfx`）全部归到一族"玻璃 / 八音盒"，不再有方波和次低频：

| 动作 | 声音 |
|---|---|
| 点按 | 五度双音玻璃 ping，跟着触点走声像 |
| 确认 | 上行两音 E6 → A6 |
| 取消 | 下落两音，很轻 |
| 双击点亮 | 四音琶音 |
| 流星 / 许愿 | 高八度三音 chime |
| 烟花 | 低通扫频的一团气（1.1kHz → 240Hz），不往 40Hz 砸 |
| 切模式 | 带通上扫的气声 |
| 摇一摇 | 132 → 96Hz 的软响 |

浏览器不允许无手势自动播声音，所以第一次按下 / 按键时才建 `AudioContext`：
手机上是点授权门那一下，桌面是第一次点击。之后音乐淡入 1.4 秒。

- 右上角 `♪ 声音` 可以随时开关，选择记在 localStorage，下次沿用（键盘 `M` 同效）
- 授权门右上角也有「声音 ON/OFF」，不用等进场景
- 页面切到后台会自动 suspend，回来再续上

## 操作

| 操作 | 说明 |
|---|---|
| 拖拽 / 单指拖动 | 环绕旋转视角（带惯性）：横向可以一直绕圈转 360°，纵向俯仰放开到 ±87°——能一路俯到树顶看同心圆环，也能仰到树底往上瞧 |
| 滚轮 / 双指捏合 | 拉近拉远 |
| 点按 / 单击 | **冲击波**：一圈光从触点向上下扩散，粒子被推开再回弹，手机伴随轻震动 |
| 双击 / 双击屏幕 | **全树点亮**：整棵树一起提亮一下（`u_flash`），同时炸一朵烟花 + 一圈冲击波 |
| 上下快滑 | **推近 / 拉远**（一次约 ±1.9 个世界单位） |
| 双指扭动 | **旋转树**：两指连线转过的角度直接带动自转，松手还带一点惯性 |
| 三指轻点 | **视角复位**：机位、俯仰、距离一起回到初始值 |
| 长按（约 0.4 秒） | **放烟花**：就在按住的位置炸开一朵 |
| 左右滑动 | 切换上一个 / 下一个模式 |
| 点中流星 | **收下一颗愿望星**，集满 5 颗触发「极光爆发」彩蛋 |
| 摇一摇手机 | 整棵树左右摆动（iOS 首次会申请运动权限） |
| 数字键 `1`–`7` | 切换光效模式 |
| `←` `→` | 上一个 / 下一个模式 |
| `空格` | 自动轮播（每 8 秒换一种） |
| `F` | 全屏 |
| `S` | 保存当前画面为 PNG |
| `H` | 隐藏 / 显示界面 |
| `M` | 声音开 / 关 |
| `Esc` | 关掉当前浮层（二维码 / 祝福对象 / 名字面板） |
| 点右上「送给 TA」 | 手机调系统分享面板，桌面弹二维码 |

第一次进来（入场结束后）会走一遍引导：左右滑 → 双击 → 点中流星 → 双指/长按，
每条 2 秒，手指一碰就收，看过一次就不再出现（`localStorage` 记 `aurora.guide`）。

触屏上手势是互斥判定的：位移小于 14px 且按下不足 0.32 秒算「点按」，超过 52px 的横向位移算「滑动」，
按住不动超过 0.38 秒算「长按」。所以旋转、滑动切模式、点按涟漪不会互相误触发。

「双击」是在点按基础上加的：两次点按间隔 < 0.3 秒、落点相距 < 44px 才算双击，第一下照常出涟漪。
「上下快滑」只在位移是横向的 1.35 倍以上且 0.62 秒内完成时才认，慢速竖拖仍然是调俯仰。
「双指扭动」和「双指捏合」共用同一组触点：距离变化改距离，角度变化改偏航。
每次手势都会在底部弹一条中英提示（`toast`），顺手用一下就记住了。

位移和提亮全部在**顶点着色器**里算（`u_waveO` / `u_waveT` / `u_shake` 三个 uniform），
静态粒子缓冲一个字节都不改，所以点多少下都不掉帧。

所以转出去的链接始终是干净的「一棵树 + 两个人名」。

组合起来就是一张可分享的"特定画面"链接。

## 怎么做的

### 树不是圆锥点云

真实的针叶树有生长结构，直接撒一个圆锥一眼就假。这里按树的生长方式**逐枝生成**：

1. **34 层轮生枝条**，每层按黄金角错开，不会叠成一条线
2. **每层的展开半径**在理论半径上叠加两条不同频率的正弦扰动，**再叠一道 6 层一个周期的"裙边"**
   （层沿外扩 11.8%、往上迅速收窄）—— 前两条给出细碎的起伏，裙边给出明显的分节，
   侧面才有"一层层枝条"的剪影，而不是光滑的锥面
3. **枝条先平展、越靠枝尖越下垂**（底层硬枝条垂得少，上层软枝条垂得多）
4. **针叶簇**沿枝条撒开，横向散布随枝尖变松
5. 枝条根部只留到 `t = 0.095` —— 完全贴到轴心会糊成一条竖亮线，跳得太开又会让树底中心空出一个 V 形缺口
6. **每层枝条数一定要少（底部 14 根、顶部 5 根）**

第 6 条是最关键、也最容易踩的一条。早先每层撒 32 根枝条，圆周被铺满，渲染出来是一个**密不透风的实心锥体**：没有缝隙、看不到内部、灯串全被淹没，看着像一团发光的雾。砍到 14 根之后枝条之间重新露出空隙，才看得见后面的轮廓和缠绕的灯串 —— 通透感来自**缝隙**，不是来自粒子多少。

### 让它是"光"而不是"点"

- **加色混合**（`blendFunc(ONE, ONE)`）：密集处自动叠加过曝趋白，这是"发光"的物理来源
- **圆角光斑**：点精灵里做高斯衰减 + 圆形遮罩收边，避免小尺寸下露出方角
- **光斑衰减必须陡**：`exp(-r2*6.2)` 而不是 `exp(-r2*3.4)`。衰减太缓时单个点就晕成一小团，密集叠加后整棵树糊成一片雾；收陡之后是"星点"而不是"雾团"
- **粒子尺寸要分三档**（小颗粒铺底、中等成团、大颗粒点缀）。所有粒子一样大会让加色叠加变成均匀噪点，颗粒层次全丢
- **两级泛光**：1/4 分辨率提取亮部 → 可分离高斯模糊（9 tap）→ 再降到 1/8 做一次更大范围的氛围光，最后叠加；
  桌面端再多摊一层 3.6 像素的大范围光雾（手机省掉这两趟），亮的地方会"溢"到周围空气里
- **树顶星芒**：顶星的位置每帧用 `vp` 矩阵投影到屏幕，喂给一个 DOM 层，由它画一个光核 + 一横一竖两道光刺。
  用 DOM 而不是着色器，是因为星芒要"大而柔"，用粒子堆出来只会变成一团白光
- **地面倒影**：以树底平面为镜，向下压缩 0.58 倍、亮度降到 44%、再给竖向抖动当作水面碎光。
  早先压到 0.46 倍、只取 17% 粒子，几乎看不见；现在取 23.5%，树下才真的"有地面"
- **换模式是渐变的**：7 套调色板在 0.65 秒里做线性插值再上传纹理，
  切模式时颜色是"走"过去的，不是"啪"一下换掉；连点也不会跳，因为每次都从当前混合态出发
- **正背面明暗**：粒子朝向相机的一侧亮、背面暗（`0.62 + 0.46*facing`），树才有体积而不是剪影
- **内外亮度差**：按"该高度的局部半径"归一化（不是树底半径，否则上半段会被误判成树心而整体压暗），外缘受光、内部压暗（`rn < 0.58` 额外衰减）

### 性能

- 约 **2.4 万**粒子，3 个 draw call 画完
- 亮度、调色、闪烁**全部在顶点着色器里算**，每帧 CPU 只在 uniform 上传几个数字
- 静态粒子一次性上传 GPU，之后不再碰；只有雪花和烟花每帧更新（不到 3000 个）
- 桌面 1280×800 下 60 fps 无压力

手机会自动走另一套参数，不需要手动设置：

- 叶子抽稀到 **46%**（约 1.34 万粒子），灯串 / 树顶星 / 雪花 / 倒影不抽，造型不受影响
- 渲染分辨率**贴近屏幕物理像素**（390×780@3x → 画布约 1421×1829）
- 只在跌破 **32 fps** 时才把分辨率让到 88%，而且只降一次 —— 宁可轻微掉帧，也不拿清晰度换

关于最后两条，是踩过坑的：早先为了保帧率把手机画布压到 1.05M 像素（约屏幕物理像素的 62%），
浏览器只好把画面拉伸上去填满屏幕，插值让**整屏发虚**——粒子再怎么调都是一团糊。
清晰度的底线是画布不能小于屏幕分辨率；性能不够应该减粒子，不能降分辨率。
- 竖屏会按宽高比把相机拉远，树不会被裁掉；底部提示自动换成手势文案

## 兼容性

需要支持 WebGL 的浏览器（Chrome / Edge / Firefox / Safari 15+ 都行）。
优先用 WebGL2 + 半浮点渲染目标（泛光层次更细腻），不支持时自动降级到 8 位。

## 想改点什么

都在 `index.html` 顶部几行常量里：

```js
const TREE_H = 6.10;   // 树高
const TREE_R = 2.52;   // 树底半径（胖瘦）
const LAYERS = 34;     // 轮生层数（层次密度）
```

配色在 `PALETTE` 数组里，每个模式 12 个颜色槽（0–5 是树体由暗到亮的六档，其余是高光 / 彩色）。

光效在着色器的 `treeLum()` 函数里，每个模式一个分支，改那一行就能换一种性格。
